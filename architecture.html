Request / Response Data Flow
1   User Interaction
FilterBar.vue — dropdown change
User selects warehouse, category, status, or time period
↓
2   Global State Update
useFilters() — reactive refs updated
selectedLocation, selectedCategory, selectedStatus, selectedPeriod
↓
3   Watcher Triggered
watch([...filters], loadData) in each View
Every view component watches the 4 filter refs; any change triggers a reload
↓
4   API Call
api.js — axios.get with URLSearchParams
getCurrentFilters() maps UI state to query params  ·  e.g. ?warehouse=Tokyo&category=sensors&month=2025-01
↓
5   Backend Filter
apply_filters() + filter_by_month()
Python loops over in-memory lists
Warehouse: exact match  ·  Category/Status: case-insensitive
Month: direct YYYY-MM substring or Q1-2025 → month array
5b   Pydantic Serialization
Response model validation
Each endpoint declares a response_model
Pydantic validates fields, serializes to JSON
Auto-generated OpenAPI schema at /docs
↓
6   Frontend State
View: data.value = response · computed properties recalculate
Raw data stored in ref()  ·  Derived metrics in computed()  ·  Vue re-renders only changed DOM nodes

Key Patterns

Filter System (Singleton)

useFilters() is a singleton composable — one shared instance across all components.

  • FilterBar updates 4 reactive refs
  • Every view watch()es those refs
  • Filter change → API re-fetch with new params
  • Filters persist across view navigation
  • getCurrentFilters() maps UI → query string

Data Loading Pattern

Consistent async pattern in every view component:

  • loading, error, data as ref()
  • loadData() called in onMounted()
  • watch(filters, loadData) for reactivity
  • Raw data in refs, display in computed()
  • Errors caught and surfaced in template

Modal Pattern

Modals live in App.vue, controlled by parent views via props/events.

  • Parent: showModal = ref(false)
  • Row click: selectedItem = item; showModal = true
  • Modal receives :is-open + :item props
  • Modal emits @close to reset parent state
  • v-if on modal component (not v-show)

Backend Filtering

All filtering done in-memory with two helper functions in main.py:

  • apply_filters(items, warehouse, category, status)
  • filter_by_month(items, month)
  • Skip filter if param is None or 'all'
  • Quarter map: Q1-2025 → ['2025-01','2025-02','2025-03']
  • Month filter: substring match on order_date

Internationalization

useI18n() provides locale-aware text and currency formatting.

  • Locale stored in localStorage as app-locale
  • English → USD ($)  ·  Japanese → JPY (¥ × 150)
  • t('nav.dashboard') nested key lookup
  • Product/customer/warehouse name translations
  • LanguageSwitcher.vue toggles locale globally

State Ownership

No Vuex/Pinia — state split across three layers:

  • Global: filters, locale, currentUser (composables)
  • View-level: loading, error, data, showModal
  • Modal-level: form fields inside the modal component
  • Backend state: in-memory only, reset on restart
  • Tasks: merged from useAuth mock + API
